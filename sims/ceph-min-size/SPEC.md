# ceph-min-size: spec

One concept: **size=2 min_size=2 blocks I/O on one failure; 3/2 does not.** Task `docs/tasks/w3/ceph-min-size.md`,
catalogue `sto-ceph-min-size` (§4.6, overlap §5.7: the one native page for size/min_size). Class stepper.

## Scene

- **Pool line:** the pool's name, `size`, `min_size`; on the HQ cluster the clock. Under it the four state counts.
- **OSDs by host** (K3 block grid): one row per host, one cell per OSD (id), up = filled, down = grey crossed, out
  (osd.22 on HQ) = dashed outline with an aside. The OSD that failed in this step carries the changed mark.
- **Every PG of the pool** (K3, `split` into rows of 16 or 32): one cell per PG by state: clean = solid green,
  degraded = hatched, inactive = red frame with ✕, no live copy = grey crossed with ∅. The watched PG (where the
  client writes) is outlined with "W" under it. Header count: PGs not serving I/O.
- **Copies of the 12 hardest-hit PGs** (K3): the client row (the last write, `W1`…), then one row per PG: its copies
  (OSD ids, `size` cells; a copy on a down OSD is grey crossed), and its state word with a mark. On a write step an
  arrow goes from the client to the watched PG: solid with the highlight when acknowledged, grey with a ✕ when it
  waits. The watched PG is the first row and is outlined.
- **Client writes** card: each write with its result; the watched PG's state as Ceph writes it. In the last step the
  card is the comparison table (below).

## State

`{ cluster, size, minSize, pool: { id, name }, pgNum, down: [osd] (order of failure), out: [osd], pgs: [group per PG],
counts: { clean, degraded, inactive, stale }, watched, zoom: [pg], writes: [{ id, pg, step, on: [osd], status:
'ack'|'blocked'|'lost' }], clock: minutes | null, ev, i }`. `ev` is the event of this step: `fail` `{ target, newly,
changed, lost }`, `later` `{ minutes, objects, stuck }`, `write` `{ write }`; `fail` also carries `hit` (every PG with a copy on the newly
down OSDs, including those whose state does not change, e.g. degraded → degraded under min_size 1), `summary` `{ compare }`.

The raw CRUSH output is not in the state: it is constant per cluster (`placement.js`) and is looked up by
`copiesOf(cluster, size, pg)`.

`placement.js` is generated by `tools/gen-placement.mjs` from the cephsim engine (`sims/cephsim/js/engine`:
`compile.js` `compileMap`, `pgmap.js` `mapPool`; straw2, `chooseleaf firstn 0 type host`, HASHPSPOOL placement).

- **hc**: cephsim `samples.js` `hyperconverged`: 3 hosts × 4 OSDs (`ceph-01` osd.0–3, `ceph-02` 4–7, `ceph-03`
  8–11), 4 TiB each, pool 1 `cephfs_data`, 128 PGs.
- **dr**: the DR estate's HQ cluster (student side: `configs/hq/hqc/ceph-osd-tree.txt`, `crushmap.txt`,
  `ceph-osd-pool-ls-detail.txt`): 5 hosts × 6 OSDs with the tree's weights, rule 0 `replicated_rule` (every device
  class), osd.22 down and out (reweight 0, so CRUSH never picks it), pool 2 `vm-rbd`, 512 PGs, size 2 min_size 2.

Size-3 sets are stored; a size-2 pool takes the first two OSDs (firstn is prefix-stable; the generator checks it for
every PG). Every set is on three different hosts (tested).

## Rules

Sources: cephsim `js/engine/pgmap.js` `pgState`; Ceph documentation "Pools" (`size`, `min_size`) and "Placement Group
States" *(check)*; faultline `samples.js` `sizeTwo` ("one disk loss does not degrade the pool, it stops it").

1. A PG is **active** (serves reads and writes) iff its live copies ≥ `min_size`.
2. Active with fewer than `size` live copies → **degraded** (Ceph: `active+undersized+degraded`); I/O continues.
   All copies live → **clean** (`active+clean`).
3. Live copies below `min_size` but > 0 → **inactive**: I/O to that PG waits; the client gets no error, it hangs.
   Ceph's state is `undersized+degraded+peered` ("peered: … cannot serve client IO due to not having enough copies to
   reach the pool's configured min_size", docs "Placement Group States", *check*). The task and cephsim's
   `pgState` say `incomplete+inactive`; `incomplete` is a different state (missing history), so this page uses
   `peered` (NOTES.md, deviations). The page's word is "inactive", as Ceph's health line ("pgs inactive").
4. No live copy → **no copy** (Ceph marks it `stale`: no OSD reports for it). Shown with ∅.
5. A write is acknowledged only once every live copy has stored it (`on` = the live copies at that moment). With
   `min_size 1` a degraded PG acknowledges a write held by one disk; when every OSD in `on` is down, the write is
   **lost**: a copy that comes back from an earlier failure is older than it (Ceph docs warn against `min_size 1`,
   *check*). A write to an inactive or stale PG is **blocked** (`on` empty) and stays blocked (no recovery here).
6. Default `min_size` of a replicated pool = `size − ⌊size/2⌋`: 2 for size 3, 1 for size 2 (docs "Pools",
   `osd_pool_default_min_size` 0 → computed, *check*). The scoping note (`cluster-design-sim-scoping.md` §5 item 3)
   says a management UI that starts at 3/2 and takes size 2 leaves min_size at 2; the explanation says so without
   naming the product. `defaultMinSize()` is tested; the page does not set min_size from it (both are params).
7. **Tie-breaks.** OSDs fail in the order of the failures; an OSD already down is not added again (a failure that
   adds nothing changes nothing: `newly` empty, no PG changes). The **watched PG** (where every write goes) is chosen among
   the PGs with a copy on the first failure's OSDs (so the first write always goes to a PG that failure touched, as
   the task's step 2 asks), then by the most copies on OSDs that are down at the end of the run, then the lowest PG
   number. The **zoom** is the
   watched PG, then the next eleven of the same order, shown in PG order. Recovery is not modelled (see
   `ceph-down-out`): states change only on a failure.

## Steps

Per failure: (1) fail — the OSD or host goes down, every PG's state recomputed; (2) write — the client writes one
object into the watched PG. On HQ the failure is followed by "ten minutes later" before the write. Last: the summary,
with the same failures run under 2/2, 3/2 and 2/1, plus the current setting when it is none of those (3/1), the
current one marked.

| preset | params | steps |
|---|---|---|
| `size2-min2` | size 2 | 3 |
| `size3-min2` | (defaults) | 3 |
| `size3-two-down` | fail2 osd.4 | 5 |
| `size2-min1` | size 2, min_size 1, fail2 osd.4 | 5 |
| `dr-s2` | HQ, size 2 | 4 |
| `host-down` | fail1 host ceph-01 | 3 |

## Params

`size` 2 / 3 (3); `minSize` 1 / 2 (2); `cluster` hc / dr (hc); hc: `fail1` osd.0 / osd.4 / osd.8 / ceph-01 (osd.0),
`fail2` none / osd.1 / osd.4 / osd.8 / ceph-02 (none); dr: `drFail` osd.15 / hq-pve-03 (osd.15). Every param resets.

## Numbers (checked with the cephsim engine, `tools/gen-placement.mjs` and `sim.test.js`)

| run | after the failures | writes |
|---|---|---|
| 2/2, osd.0 | 111 clean, **17 inactive** | W1 blocked |
| 3/2, osd.0 | 98 clean, **30 degraded**, 0 inactive | W1 acknowledged on 2 copies |
| 3/2, osd.0 + osd.4 | after osd.0 as above; then 71 clean, 50 degraded, **7 inactive** | W1 ack (2 copies), W2 blocked |
| 2/1, osd.0 + osd.4 | after osd.0: 111 clean, 17 degraded; then 82 clean, 44 degraded, **2 no copy** | W1 ack on osd.4 only, then **lost**; W2 blocked |
| HQ 2/2, osd.15 | 482 clean, **30 inactive** of 512 | W1 blocked |
| 3/2, ceph-01 | **128 degraded**, 0 inactive | W1 ack |

The task estimated `dr-s2` at "≈ 2 × (osd.15 weight / total) × 512 ≈ 33" (check with the engine): the engine gives
**30** (30 PGs of vm-rbd have a copy on osd.15; cephfs_data, 256 PGs, has 18). Comparison rows the summary shows
(not in the task): HQ 3/2 → 0 inactive, 49 degraded; 2/2 with osd.0 + osd.4 → 44 inactive, 2 no copy; HQ 2/2 with
the whole hq-pve-03 down → 163 inactive.

**Ten minutes later (HQ).** S2: osd.15 dies at 10:40, "ten minutes later several VMs hang". The step moves the clock
to 10:50 and adds one illustration: a 100 GiB virtual machine disk is 100 × 1024 / 4 = 25,600 objects of 4 MiB (the
block device's default object size, *check*), spread over all 512 PGs, so about 25,600 × 30 / 512 = **1,500** of them
sit in stopped PGs; every machine that touches one waits. With no PG below min_size (size 3, or min_size 1) the step
says the machines keep running.
