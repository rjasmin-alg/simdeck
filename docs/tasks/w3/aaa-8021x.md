## Model and presets

- **Scene:** K1 message sequence chart with three lifelines: supplicant (laptop), authenticator (switch port or
  Wi-Fi AP), authentication server (RADIUS). The port is drawn as a gate on the laptop's link: closed (only EAPOL
  passes) or open. A side column maps each message to the book's four steps: identification, authentication,
  access control (authorization), audit (accounting).
- **State:** `{ phase, port: 'unauthorized'|'authorized', vlan, msgs: [{from, to, proto: 'EAPOL'|'RADIUS',
  name}], aaa: {identified, authenticated, authorized, accounted}, outcome }`.
- **One step:** one message on the chart, then the port state update: 1 link up, port unauthorized (only EAPOL);
  2 laptop tries DHCP → dropped at the port; 3 EAP-Request/Identity (authenticator → supplicant); 4
  EAP-Response/Identity ("ana@fakultet") = identification; 5 switch wraps it in RADIUS Access-Request to the
  server; 6–9 EAP method rounds as Access-Challenge / Access-Request pairs (shown as one folded pair per round;
  e.g. PEAP or EAP-TLS) = authentication; 10 Access-Accept with VLAN attribute = authorization; 11 EAP-Success to
  the laptop; 12 port authorized, VLAN assigned; 13 DHCP now passes; 14 Accounting-Request Start = accounting.
- **Rules:**
  1. Until authenticated the controlled port passes only EAPOL frames (IEEE 802.1X-2020, controlled/uncontrolled
     port *(check clause)*).
  2. The authenticator does not decide: it relays EAP between laptop (EAPOL) and server (RADIUS) (RFC 3579 RADIUS
     support for EAP; RFC 3748 EAP).
  3. RADIUS: Access-Request, Access-Challenge, Access-Accept, Access-Reject on UDP 1812 (RFC 2865); accounting on
     UDP 1813 (RFC 2866).
  4. Access-Accept may carry a VLAN (Tunnel-Type = VLAN, Tunnel-Private-Group-ID) (RFC 3580 §3.31 *(check)*).
  5. Access-Reject → EAP-Failure, the port stays unauthorized (RFC 3579).
  6. The order identification → authentication → access control → audit, and AAA = Authentication,
     Authorization, Accounting with identification as its first step (URM ch18 „Tko je to, i smije li…" and
     figure `fig:aaa-koraci`).
  7. In enterprise Wi-Fi, 802.1X produces the PMK the 4-way handshake then uses; in personal mode the PMK comes
     from the shared password (URM ch17 „Sigurnost bežične mreže…", Primjer 5).
  Edge case: server unreachable → no answer; after the switch's timeout the port stays closed (timer value
  *(check)*; show "no reply", not a number).
- **Params:** `medium` choice wired/Wi-Fi (wired); `credentials` choice correct/wrong (correct); `server` toggle up
  (on); `method` choice PEAP/EAP-TLS (PEAP; only the round count and labels change: 3 vs 2 folded rounds
  *(check)*).
- **Presets:**
  - `book` correct login on wired port: Accept, VLAN 20 (staff), DHCP passes at step 13, accounting starts.
    Order from URM ch18 (AAA figure); messages from RFC 2865/3579; VLAN number derived.
  - `reject` wrong password: Access-Reject, EAP-Failure, port stays closed; DHCP still dropped. Derived from RFCs.
  - `server-down` RADIUS unreachable: requests unanswered, port closed. Derived.
  - `wifi` enterprise Wi-Fi (URM ch17 Primjer 5): same EAP exchange, then "PMK delivered → 4-way handshake"
    as the last step instead of DHCP. From URM ch17 Primjer 5.
- **Steps:** `book` 14, `reject` 11, `server-down` 7, `wifi` 14.
- **Legend:** EAPOL message (solid arrow), RADIUS message (dashed arrow), dropped frame (arrow ending at the gate,
  cross), port closed (gate shape) / open, AAA step badge (I, A, A, A), changed (kit highlight on the new message
  and on the gate when it changes).
- **Captions:** hr: "Preklopnik ne zna lozinku: EAP poruku samo prepakira u RADIUS Access-Request." / en: "The
  switch does not know the password: it just repacks the EAP message into a RADIUS Access-Request." — hr:
  "Access-Accept s VLAN-om 20: tek sada vrata propuštaju DHCP." / en: "Access-Accept with VLAN 20: only now does
  the port let DHCP through."
- **Terms:** supplicant — molitelj *(check)* / klijent; authenticator — autentikator *(check)*; authentication
  server — poslužitelj za autentikaciju (URM ch17); identification — identifikacija; authentication —
  autentikacija; access control (authorization) — nadzor pristupa; audit (accounting) — revizija; port-based
  access control — nadzor pristupa po *portu*.
- **Misconceptions:** the switch checks the password; authentication and authorization are the same step (URM
  ch18 Šire o temi); 802.1X encrypts the wired link.
- **Out of scope:** EAP method internals (TLS inside PEAP), MAB, MACsec, TACACS+, the 4-way handshake itself.

6. Checks and screenshots (COMMON.md §7); `NOTES.md` with decisions, sources and timing.
