Ethernet — IEEE 802.3

Ethernet is the dominant L2 framing format. The Ethernet II (DIX) variant is used almost universally; IEEE 802.3 SNAP survives in legacy bridged environments. Click any field to inspect it.

Jumbo frames: Standard MTU is 1500 B (payload). Jumbo frames (typically 9000 B) require end-to-end NIC, switch, and OS support. Linux: ip link set eth0 mtu 9000. Benefits: reduced CPU overhead for iSCSI/NFS. Risk: silent drops at any hop not configured for jumbos — no ICMP PTB generated for L2 MTU mismatches.

Livewire (PRISM packet header)

Livewire (also called PRISM capture header or Wireshark "PRISM monitor mode") is not a network protocol per se — it is a capture metadata header prepended by wireless NICs in monitor mode before the 802.11 frame. Used in 802.11 packet capture pipelines. Carries RSSI, channel, rate, etc.

802.1Q VLAN · 802.1ad QinQ · PVLAN

VLANs partition a physical L2 domain into isolated broadcast domains. 802.1Q inserts a 4-byte tag. 802.1ad (QinQ) stacks two tags for provider isolation. PVLAN (Private VLAN, RFC 5517) further subdivides a single VLAN into isolated sub-domains without consuming multiple VLAN IDs.

MTU impact: Each tag adds 4 B. QinQ total overhead = 8 B → effective payload MTU = 1492 B (or frame grows to 1526 B). Many switches need explicit "system mtu 1526" or equivalent to avoid silently truncating double-tagged frames.

Private VLAN (PVLAN) — RFC 5517 / Cisco

PVLAN is a port-level isolation mechanism operating within a single primary VLAN. It does NOT add a different EtherType or tag structure — the frame on-wire still uses standard 802.1Q. The isolation is enforced by switch port associations.

PVLAN Port Types
Promiscuous
Can talk to all ports in primary VLAN. Routers, firewalls.
Isolated
Only talks to promiscuous. Cannot talk to any community port or other isolated ports. Typical: servers in DMZ.
Community
Talks to its own community + promiscuous. Cannot talk to isolated or other communities.
PVLAN Sub-VLAN Mapping
Primary VLAN: VLAN 100
↳ Isolated secondary: VLAN 101
↳ Community A secondary: VLAN 102
↳ Community B secondary: VLAN 103

Traffic still tagged with primary VLAN 100 at egress. Secondary VLANs are local switch constructs — not propagated via VTP or visible externally.

⚠ PVLAN frames on trunk ports use the primary VLAN tag only.
# Cisco IOS PVLAN config skeleton
vlan 100
  private-vlan primary

vlan 101
  private-vlan isolated

vlan 100
  private-vlan association 101   # bind isolated 101 to primary 100

interface GigabitEthernet0/1         # promiscuous (router/firewall uplink)
  switchport mode private-vlan promiscuous
  switchport private-vlan mapping 100 101

interface GigabitEthernet0/2         # isolated host
  switchport mode private-vlan host
  switchport private-vlan host-association 100 101

VXLAN · GENEVE · NVGRE · LISP overlay at L2

Overlay protocols tunnel L2 frames over L3 UDP/IP, extending virtual broadcast domains across routed boundaries. Primary driver: data center multi-tenancy and VM mobility across racks/DCs. VXLAN dominates; GENEVE is its flexible successor with metadata extension support (the basis for OVN, Cilium, NSH transport).

VXLAN MTU overhead: Outer Eth(14) + IP(20) + UDP(8) + VXLAN(8) = 50 bytes. Inner frame MTU = 1500 − 50 = 1450 bytes. With outer 802.1Q tag: 1446 B. Physical underlay must run MTU ≥ 1550 B (typically 9000 B jumbo). If not: fragmentation of the outer UDP packet occurs at L3, or inner TCP MSS clamping must be applied.

GENEVE — RFC 8926

GENEVE is the extensible successor to VXLAN/NVGRE/STT. The key differentiator: a variable-length options field carrying TLV (Type-Length-Value) metadata — enables NSH-like service chaining, OVN context passing, and hardware offload hints without a separate encapsulation layer.

ECMP problem with NVGRE/GRE: GRE (IP proto 47) gives L3 switches no entropy to hash on — src/dst IPs are the same for all flows between a VTEP pair. VSID/FlowID requires deep-packet inspection. This is why VXLAN/GENEVE (UDP-based) dominate: the outer UDP src port is entropy-filled, enabling standard 5-tuple ECMP on any commodity switch.

AH vs ESP
AH (proto 51): Authenticates IP header + payload. No encryption. Incompatible with NAT (IP header changes break ICV).

ESP (proto 50): Encrypts + authenticates payload. Header not authenticated (transport) or outer header not (tunnel). NAT-T wraps ESP in UDP/4500.
IP-in-IP (IPIP)
IP proto 4 = IPv4 in IPv4. Proto 41 = IPv6 in IPv4 (6in4 tunnel, RFC 4213). No encryption, no overhead beyond outer IP header (20B). Used in 6to4, Teredo, 6rd. Simplest possible L3-in-L3 tunnel.
SRv6 (Segment Routing)
Uses IPv6 Routing Extension Header (Next Header = 43, Routing Type = 4). Segment list = ordered array of IPv6 SIDs. Active segment = DST IPv6 field (updated hop-by-hop). Replaces MPLS TE in many SP deployments. No additional encapsulation needed.

NSH — Network Service Header (RFC 8300)

NSH is a service function chaining header. It does not encapsulate by itself — it rides inside VXLAN-GPE (RFC 8676) or GRE. Carries a Service Path ID and Service Index to steer traffic through an ordered chain of VNFs (firewall → IDS → DPI → load balancer).

LISP separates endpoint identity (EID) from routing locators (RLOC), solving the routing table scaling problem. EIDs are the inner addresses; RLOCs are the tunnel endpoints. LISP uses a Map-Server/Map-Resolver infrastructure to resolve EID→RLOC mappings.

Other notable L2/L2.5 protocols

IEEE 802.1AE
MACsec
L2 encryption at wire speed. Inserts a 16-byte SecTAG between Src MAC and EtherType (EtherType = 0x88E5). Encrypts and authenticates from EtherType to FCS. Operates per-port or per-flow. Hardware-enforced — cannot be bypassed at L3. Used in campus/DC for east-west encryption. Note: each hop decrypts/re-encrypts (hop-by-hop, not end-to-end).
IEEE 802.1ah
PBB (Provider Backbone Bridge)
MAC-in-MAC encapsulation for provider networks. Adds outer B-MAC (backbone) header (14B) + B-TAG (4B, 0x88A8) + I-TAG (6B, 0x88E7). The 24-bit I-SID (service instance ID) in I-TAG = 16M services. Provider core only sees B-MACs — customer MACs never leak into backbone. Predecessor to EVPN in many deployments.
RFC 7364
TRILL (Transparent Interconnect of Lots of Links)
IS-IS-based L2 routing protocol. RBridges (routing bridges) use a 6-byte TRILL header (EtherType 0x22F3). Hop count prevents loops. Supports ECMP at L2 natively via equal-cost ECMP tree computation. Largely superseded by VXLAN+BGP EVPN but still deployed in some DC fabrics.
IEEE 802.1aq
SPB (Shortest Path Bridging)
IS-IS-computed shortest paths for Ethernet. Supports ECMP without STP. Two modes: SPBM (MAC-in-MAC, uses PBB I-SID) and SPBV (VLAN-based). Used in Avaya/Extreme enterprise fabrics. Less common than TRILL in DC, but strong in enterprise campus.
RFC 5462
MPLS-TP
Transport Profile for MPLS — deterministic, OAM-rich variant for carrier transport networks. Eliminates PHP, uses explicit NULL at bottom of stack. Adds G-ACh (Generic Associated Channel) for OAM. No IP dependency — runs over Ethernet or SDH/SONET. Competes with OTN in SP metro.
IEEE 802.3ah
EFM OAM (Ethernet in the First Mile)
L2 OAM protocol. Slow-protocol EtherType 0x8809, subtype 0x03. OAMPDU types: Information, Event Notification, Variable Request/Response, Loopback Control. Runs on a single link. Enables remote loopback, link monitoring, fault signaling. Distinct from 802.1ag (CFM, multipoint OAM).

IP Fragmentation & Path MTU Discovery

IPv4 fragmentation occurs when a datagram exceeds an interface MTU. IPv6 routers never fragment — the originating host must do PMTUD. The Identification field, MF flag, and Fragment Offset are the reassembly mechanism.

IPv4 fragmentation field anatomy

IPv4 fragment fields — Flags(3) + Fragment Offset(13) in 2 bytes
0
1 bit
DF
1 bit
MF
1 bit
FRAGMENT OFFSET (×8 bytes)
13 bits
Fragmentation attack vectors: (1) Teardrop — overlapping fragment offsets crash old TCP/IP stacks. (2) Tiny fragment attack — fragment so small that TCP flags split across fragments, bypassing stateless ACL inspection. Defense: require MF=0 for all TCP first fragments (i.e., first fragment must contain full TCP header). (3) Fragment reassembly timeout exhaustion — send first fragment only, forcing target to hold partial datagrams until TTL (RFC 791 requires 15-second minimum wait). (4) VXLAN fragmentation: if outer UDP is fragmented, the inner IP header lands in a later fragment — stateful firewalls can't match the session.

Path MTU Discovery (PMTUD) — RFC 1191 (IPv4), RFC 8201 (IPv6)

Algorithm
1. Send with DF=1, size = suspected MTU
2. If ICMP Type 3 Code 4 received → reduce to suggested MTU
3. Retry with smaller size
4. Repeat until no ICMP → MTU found
5. Cache MTU per destination (5–10 min timeout)

Failure mode: ICMP black holes — firewalls silently drop ICMP Type 3 → sender never learns MTU → TCP hangs after 3WHS (data stalls). Fix: TCP MSS clamping via iptables TCPMSS target.
