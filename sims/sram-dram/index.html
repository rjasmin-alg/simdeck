SRAM Characteristics THEORY

Bistable Latch — No Refresh

The cross-coupled inverter pair has two stable states. As long as V_DD is maintained, the positive feedback loop holds the stored bit indefinitely. There is no charge leakage path — the state is actively driven by the CMOS transistors. This means zero refresh overhead, but 6 transistors per bit vs. DRAM's 1T1C.

Read Operation (Differential Sensing)

Both BL and BL̄ are precharged to V_DD/2 (or V_DD). When WL goes high, the stored Q and Q̄ drive a small differential voltage on the bitlines through N3/N4. The sense amplifier detects this ~50-100mV differential and amplifies it. The read is non-destructive — the latch retains its state because it actively drives the bitlines.

Write Operation (Overpower the Latch)

The write driver must overpower the cross-coupled latch. BL is driven to the desired value, BL̄ to the complement. With WL high, the bitline drivers (stronger than the cell's PMOS pull-ups) force the internal nodes to flip. The write margin depends on the β ratio (pull-down vs. access transistor sizing) — careful transistor sizing is critical for stability.

Static Power & Leakage

While static current is near-zero in the hold state (only sub-threshold leakage), at advanced nodes (≤7nm), gate leakage and GIDL become significant. Total SRAM array leakage can dominate power in standby. Sleep transistors (power gating) and SVT/HVT cell variants are used to manage leakage in cache arrays.

DRAM Characteristics THEORY

Capacitive Storage — Volatile by Design

Unlike SRAM's active latch, DRAM stores charge on a tiny trench or stacked capacitor (~20fF at advanced nodes). Junction leakage through the access transistor, sub-threshold current, and GIDL (Gate-Induced Drain Leakage) continuously drain this charge. At 7nm nodes, retention time can drop below 32ms in worst-case cells (Variable Retention Time — VRT).

Destructive Read

When WL goes high, charge sharing between C_s (~20fF) and C_BL (~200fF) develops a small voltage on the bitline: ΔV = V_cell × C_s / (C_s + C_BL). For a full charge, this is only ~50-100mV. The sense amplifier detects and amplifies this differential — but the read destroys the stored charge. The controller must write-back (restore) the amplified value immediately after every read.

Refresh — The 64ms Contract

JEDEC specifies that every DRAM row must be refreshed within 64ms (32ms at high temperatures). With 8K-16K rows per bank, the memory controller issues REF commands every 7.8µs (tREFI). Each refresh is essentially a read + write-back. Refresh overhead consumes 5-10% of bandwidth in DDR4 and grows with density — DDR5 introduces per-bank refresh to mitigate this.

Why Not Just Use SRAM?

Density: 1T1C = ~6F² per bit vs. 6T SRAM = ~100-150F² per bit. At $3-5/GB for DRAM vs. $500+/GB equivalent for SRAM (cache), the economics dictate the memory hierarchy: SRAM for L1/L2/L3 cache (fast, expensive, low density), DRAM for main memory (slower, cheap, high density). This is the fundamental tension of the memory wall.

Memory Hierarchy Context ARCH

The Memory Wall

CPU clock speeds outpace memory bandwidth improvement by ~10x per decade. The solution: a deep cache hierarchy (SRAM L1 → L2 → L3 → DRAM) trading off latency, capacity, and cost. Modern CPUs spend ~30-50% of die area on cache SRAM.

Security Implications VULN

Why DRAM Is Attacked

DRAM's charge-based storage creates a physical side-channel: electromagnetic coupling between adjacent cells (Rowhammer), and timing differences between cache hits and DRAM accesses enable Flush+Reload (Spectre/Meltdown). SRAM's bistable latch is immune to disturbance errors but its cache-line presence/absence is the side-channel itself.

Future: Emerging Memories NEXT

Beyond SRAM & DRAM

eMRAM: STT-MRAM as SRAM replacement in L2 (non-volatile, ~2× density). HBM: 3D-stacked DRAM with TSVs for bandwidth. CXL: Memory pooling breaking the DRAM-per-socket model. PIM: Processing-in-memory to break the memory wall by moving compute to data.
