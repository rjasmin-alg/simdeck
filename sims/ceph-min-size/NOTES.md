# ceph-min-size: notes

New stepper (task `docs/tasks/w3/ceph-min-size.md`, catalogue `sto-ceph-min-size`, wave 3). Kit view **K3**
(`Simdeck.blockGrid`) draws all three grids: the OSDs by host, every PG of the pool, and the copies of twelve PGs with
the client's write arrow. Rules and expected numbers: `SPEC.md`.

## Decisions

- **Three grids, not one OSD × PG matrix.** The task's scene had rows = OSDs and columns = 128 PGs; at 1920×1080 that
  is 12 × 128 cells (and 30 × 512 on the HQ cluster), too small to read. Instead: OSDs by host (who is down), every PG
  as one cell coloured by state (how much of the pool stops), and a 12-PG zoom whose rows are PGs and cells their
  copies (why: which OSDs held them). The task's "12-PG zoom shows acting sets" is that third grid.
- **The watched PG** (tie-break, SPEC rule 7): every write of a run goes to one PG: among those with a copy on the
  first failure's OSDs, the one with the most copies on the OSDs that fail during the run, then the lowest number. So in `size2-min1` the first write lands in a PG whose second copy
  dies next (the lost write of rule 5 is on the page, not only in the tests), and in `size3-two-down` the second write
  goes to a PG that lost both. It is outlined in the PG grid ("W") and is the zoom's first row.
- **The zoom set** is fixed for a run (the eleven next hardest-hit PGs, in PG order), so rows do not jump between
  steps; before any failure it already shows the PGs the run will hit.
- **Changed marks**: only the OSD that failed in this step (OSD grid), the state words in the zoom and the counts.
  Not on PG cells: the kit's changed fill hides the hatch and the frame, so a step that degrades 31 PGs became a
  yellow field. The new states show by their pattern.
- **State marks drawn in CSS.** The page font (Atkinson Hyperlegible) has no ⏸ or ◐, and the fallback drew a thin
  bar and a sliver; degraded is a CSS half disc, inactive a CSS pause sign (two bars), ✓ ∅ ✕ stay text. Captions use
  words, no symbols except ✓ and ∅.
- **HQ cluster (`dr-s2`)**: built from the student-side estate configs (tree weights, rule 0 over every device
  class, osd.22 down and out). The "ten minutes later" step moves the clock and explains the hang with numbers:
  a 100 GiB machine disk has ~1,500 of its 25,600 objects in the 30 stopped PGs. Recovery after the down→out interval
  is not modelled (out of scope, `ceph-down-out`); the caption does not claim anything about it.
- **Comparison at the end** (COMMON §11, "run the others to their own end"): the summary table runs the same
  failures under 2/2, 3/2 and 2/1 (and 3/1 when that is the current setting) and marks the current one.
- **Second write**: it goes to the same PG as the first, which the second failure may not touch (osd.0 then osd.1 on
  the same host); the task's "a PG that contained that OSD" holds for the first write only. One PG per run keeps the
  story (acknowledged, then blocked or lost) in one row.
- **Placement fixture**: `placement.js` is generated by `tools/gen-placement.mjs` from the cephsim engine already in
  `sims/cephsim/` (COMMON §6: copy, do not link). It stores size-3 sets; size 2 takes the first two (firstn is
  prefix-stable, checked by the generator). The page loads it like `sim.js`; the build inlines it. The generator is a
  dev tool (node, ESM, imports `../../cephsim/js`); the page never loads it.
- **Params**: `cluster` (hc / dr) was added so the DR preset is one more setting, not a second model; the failure
  controls change with it (`fail1`, `fail2` on hc, `drFail` on dr). Host options are labelled with the host name
  alone (`ceph-01`); the control label says the failure.
- **Concepts, not tools**: Ceph is named (NLA T26 teaches it); `size`, `min_size`, the PG state strings and pool
  names are the subject. The management UI that leaves min_size at 2 is "a management interface", not named.

## Deviations from the task

- **Rule 3 state name**: `undersized+degraded+peered`, not `incomplete+inactive`. Ceph's "Placement Group States"
  defines *peered* as "cannot serve client IO due to not having enough copies to reach the pool's configured
  min_size" and *incomplete* as missing write history *(check: from memory, no network)*; cephsim's `pgState` (and so
  the task) uses `incomplete+inactive`. The page's group word is "inactive", as Ceph's health line says. A defect
  note for cephsim's owner, not fixed here (another sim's folder).
- **Rule 4 state name**: shown as `stale`, without the last-known flags Ceph keeps after it.
- **`dr-s2` count**: 30 of 512 (engine), not the task's estimate ≈ 33.
- **Scene**: three grids instead of one OSD × PG matrix (Decisions).
- **State**: `raw` is not in the state (constant per cluster, in `placement.js`); added `pool`, `out`, `pgs`,
  `watched`, `zoom`, `writes` (a list, not one `write`), `clock`, `ev`.
- **Params**: `cluster` and `drFail` added; `fail` is two params (`fail1`, `fail2`) so the two-failure presets can be
  built and changed from the panel.
- **Legend**: no separate "down OSD row"; a down OSD's cells are grey crossed in the OSD grid and in the zoom.

## Shared requests

- **K3 `blockGrid`**: a way to mark a cell as changed without hiding its kind (an outline or a corner dot instead of
  the fill), so a state change of many cells can be shown in place. Worked around: no changed mark on PG cells.
- **Kit controls** (`kit.css`): hidden controls: `.sd-ctl[hidden]` is still displayed when a page lays the controls out as a grid; the
  page adds `display: none` for it. A kit rule `.sd-ctl[hidden] { display: none }` would cover every page.
