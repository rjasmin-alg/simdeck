## State

`{ iface: { name, admin, addr: null | { ip, prefix } }, routes: [{ dst, prefix, via, dev, metric, proto, scope, src }],
nsswitch, hosts: [{ ip, names }], profile: { name, dns }, resolv: { nameserver }, dnsZone, broke, cmd, text, phases,
lookup, name, packet, route, dest, out, exit, event }`.

- `phases` (the task's `steps`, renamed so it does not read as the kit's steps): the phases of this step's command,
  `[{ phase: 'read' | 'name' | 'route' | 'link' | 'change', place: 'iface' | 'route' | 'name' | 'link', result: 'ok' |
  'fail' | 'info' | 'pending' }]`.
- `lookup`: the route lookup the table shows: `{ purpose: 'dest' | 'dns' | 'gateway', dest, matches, winner, order }`.
- `name`: the name lookup: `{ name, ip, from, trace: [{ src, result: 'hit' | 'miss' | 'unavail' | 'skip', why }],
  dns, err: null | 'tempfail' | 'notfound' }`.
- `packet`: `{ kind: 'ping' | 'dns', to, hop, via, reply }`; `route`: `ip route get`'s answer `{ ok, row, via, src, hop }`.
- `event`: `{ kind, rung, changed, added, removed }`: the command, the ladder rung that failed (rule 7), what it read
  or changed.

## One step

One command of the script, run on the configuration the commands before it left. Its phases go in a fixed order:

1. **the name**, if the command has one (rule 1);
2. **the route lookup** for the address (rules 2–6);
3. **the packet** to the next hop and back (rule 6).

The first phase that fails ends the step; the later ones stay `pending` (grey). Commands that only read or change a
place have one phase (`read` or `change`). Step 0 is the configuration with the `break` applied and no command run.

## Rules

1. **Names.** A name is resolved by the sources of the `hosts:` line, in order, until one has a result (nsswitch.conf(5),
   UL "Ime umjesto adrese"). `files`: the first line of `/etc/hosts` that names it, answering before DNS is asked, and
   silently (UL Primjer 2). `dns`: needs a route to the `nameserver` of `/etc/resolv.conf` (no route: the source is
   unavailable) and a server answering there (none: a time-out, unavailable); the zone has the name or not.
   `myhostname`: the host's own name, to its address, or `127.0.0.2` without one (nss-myhostname(8) *(check)*).
   `getent hosts` exit status 2 = not found (UL, getent(1)); its line is the address padded to 15 columns, then the
   names. `ping` with a name that does not resolve: `ping: <name>: Temporary failure in name resolution` when a source
   was unavailable, `Name or service not known` when every source said no; exit 2 *(check)*.
2. **Route lookup.** Of the routes whose prefix contains the destination, the **longest prefix wins**; `default` is
   `0/0` and matches every address with length 0 (UL; RFC 4632; ip-route(8); LPM as in `routing-table`).
3. **Tie-breaks.** Equal prefix length → the lowest `metric` (ip-route(8) *(check)*); equal metric → the first in
   table order. Only the same prefix can tie (two `default` routes, metric 100 and 600). The table is listed by
   network, then the longer prefix first, then metric *(check)*; `ip route` prints `proto boot` and metric 0 as nothing.
4. **Connected routes** (`proto kernel scope link`) exist only while the interface has an address in that prefix and is
   administratively up. Removing the device's last IPv4 address flushes every route on the device, the connected and the
   DHCP default route among them *(check)*; `ip link set down` removes every route on the device *(check)*.
5. **Next hop.** On-link destination (the winning row has no `via`) → no `via` in `ip route get` (UL: `ip route get
   192.168.122.57` on democli1); off-link → `via` the gateway (UL: `1.1.1.1 via 192.168.122.1 dev enp1s0 src
   192.168.122.57 uid 1000`). No matching route → `RTNETLINK answers: Network is unreachable` (exit 2) / `ping: connect:
   Network is unreachable` (exit 2) *(check)*. A new route's gateway must be on the link, else `Error: Nexthop has
   invalid gateway.` (exit 2) *(check)*.
6. **Source and the other side.** The source address is the route's `src`, else the interface's address. The packet
   goes to the next hop; a reply comes only if someone is at the next hop and, beyond the gateway, at the destination.
   A ping without a reply: 100 % packet loss, exit 1, no line per packet (UL, `ping -c 2 -W 1 192.168.122.99`); the
   scripts use `ping -c1 -W1 -W1` for that reason (without `-W` an on-link host that is not there gives `Destination Host
   Unreachable` lines once ARP fails).
7. **The ladder** (UL "Dijagnostika: pitanje po pitanje"): link → address → route → the other side. A failed route
   lookup is the *address* rung when the interface has no address (no address, no connected route), else the *route*
   rung; a name lookup that fails for want of a route to the name server belongs to the same rung, not to the name; no
   reply is *the other side*. A ping that finds no route sends nothing (no packet in the step). A "no" at a lower rung makes the higher ones meaningless; the caption names the
   rung.

## Params

- `script`: the preset's command list (the six below); changing it resets to step 0.
- `break`: `none` / `address` / `route` / `resolver` / `hosts`, default `none`; live: the same commands re-run at the
  current step. `address`: `ip addr del` (rule 4: the table empties). `route`: the default route is gone. `resolver`:
  the profile's `ipv4.dns` and the file say `192.168.122.250`, where nobody answers (*assumption:* the profile also has
  `ipv4.ignore-auto-dns yes`; on a DHCP profile without it the DHCP server `.1` would be listed too and glibc would
  fall back to it after the time-out). `hosts`: `/etc/hosts` has the
  stale line `192.168.122.99 democli1`.
- `target`: `by-name` / `by-address`, default `by-name`: a ping whose destination has a name uses the name or the
  address (no name phase).

`resolver` and `hosts` break nothing in the healthy script.

**The profile fix** brings the connection up again: the address, the connected and default routes and the name server
come back from the profile *(check: what `connection up` does to routes added by hand is not modelled; no preset adds
routes and runs the fix)*.

## Out of scope

Policy routing and several tables (`lnx-policy-routing`), the `local` table (a ping to the host's own address), IPv6
(left out of the outputs), ARP, DHCP, firewalls and the silent `ping` of UL Primjer 3, oper-state against admin-state
(text only), recursive DNS (`inet-dns-resolution`), the `search` list (with `search lab.local` a DNS answer for
`democli1` would likely print as `democli1.lab.local`; the model prints the name as asked).
