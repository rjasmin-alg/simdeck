How Rowhammer Works THEORY

1. DRAM Cell Structure

Each bit is stored as charge in a ~20fF trench capacitor accessed via a single transistor. At sub-30nm process nodes, inter-cell parasitic coupling capacitance becomes significant relative to storage capacitance.

2. The Disturbance Mechanism

When a wordline is activated, voltage swings on the aggressor row's cells (~1.2V) induce charge injection into adjacent rows via parasitic capacitive coupling (cell-to-cell) and hot-carrier injection through the substrate. Repeated ACT→PRE cycles accumulate this disturbance faster than the normal 64ms refresh interval can restore it.

3. Exploitation (double-sided)

The attacker targets two aggressor rows flanking a victim row — a double-sided hammer. Using CLFLUSH (x86) or uncacheable memory mappings to bypass the cache hierarchy, the attacker forces repeated row activations in DRAM. By exploiting /proc/self/pagemap or huge pages to determine physical addresses, the attacker can target specific victim pages — e.g., page table entries — to gain write access to arbitrary physical memory.

4. Mitigations

TRR (Target Row Refresh): DRAM controller tracks frequently activated rows and preemptively refreshes neighbors. ECC: Detects single-bit errors (but multi-bit Rowhammer can defeat SECDED). PARA: Probabilistic Adjacent Row Activation — each ACT has a small probability of refreshing neighbors. pTRR/RFM: DDR5 introduces Refresh Management to explicitly handle hammer patterns.

5. CVE Timeline

2014: Kim et al. publish original disturbance error paper. 2015: Google Project Zero demonstrates privilege escalation via Rowhammer (CVE-2015-0565). 2016: Flip Feng Shui — VM escape via Rowhammer + memory deduplication. 2018: Throwhammer — remote Rowhammer over RDMA. 2020: TRRespass — bypasses all deployed TRR implementations. 2021: SMASH — JavaScript-based Rowhammer in the browser.
